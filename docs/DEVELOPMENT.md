# Whileplay 开发指南

## 环境

- Node.js `^22.19.0 || >=24.0.0` 和 npm。
- 调试宿主集成时，准备一份已安装依赖并完成构建的 DeepSeek Harness 源码。
- Windows 的本地预览脚本使用 PowerShell。

先运行 `npm ci` 安装 Zod 校验依赖和 chess.js 棋规引擎。客户端交互测试复用 Harness 已安装的 React、ReactDOM 和 jsdom；真实页面测试复用其 Playwright。

## 从源码安装

克隆仓库并安装依赖、打包：

```sh
git clone https://github.com/monster-cli/dsh-whileplay.git
cd dsh-whileplay
npm ci
npm pack
```

`npm pack` 会自动构建并生成 `dsh-whileplay-0.4.0.tgz`。安装后重启 Web profile：

```sh
dsh plugin --profile web add ./dsh-whileplay-0.4.0.tgz
dsh web
```

构建使用 Node.js 内置工具，浏览器中的 React 由 Harness 提供。

## 构建与基础测试

在 Whileplay 项目根目录运行：

```sh
npm run build
npm test
```

构建生成 `client.js`。该文件是插件分发入口，需要与源码一起提交。

## 棋类游戏

游戏库的「棋类」分类包含国际象棋和五子棋。两款均支持本地人机对弈、同屏双人、悔棋、棋谱、极简显示以及按会话自动存档。电脑走棋不调用模型；任务结束、需要用户操作或页面失焦时暂停，重新打开存档后需手动继续。

- 国际象棋：人机模式玩家执白先行；合法落点、将军和将杀、逼和、王车易位、吃过路兵与四种升变均由 chess.js 校验。电脑使用有时间预算的浅层搜索，定位为休闲对手。
- 五子棋：人机模式玩家执黑先行；15×15 自由规则，五连及长连获胜，无禁手。电脑优先争胜和防守对方的立即获胜点。
- `src/board-games.js` 提供规则适配、电脑走棋和存档；`src/board-ui.js` 与 `src/board.css` 提供界面。构建将 chess.js 隔离打包到客户端并保留 BSD-2-Clause 许可声明，不依赖运行时 CDN。
- `tests/board-games.test.mjs` 覆盖棋规、电脑应手和存档；客户端测试覆盖实际落子、取消电脑应手、悔棋、切换游戏后恢复及极简模式。

棋类功能从 v0.4.0 开始提供。v0.3.0 安装包不包含这两款游戏。

未设置 `DSH_SOURCE_ROOT` 时，客户端交互测试会明确显示为跳过；规则与窗口几何测试照常运行。此结果不代表客户端集成已通过。

## 客户端交互测试

设置 `DSH_SOURCE_ROOT`，指向已经安装依赖并构建完成的 Harness 源码目录。以下示例将两个仓库放在同一父目录下。

PowerShell：

```powershell
$env:DSH_SOURCE_ROOT = (Resolve-Path '../deepseek-harness').Path
npm run test:client
```

macOS / Linux shell：

```sh
export DSH_SOURCE_ROOT="$(cd ../deepseek-harness && pwd)"
npm run test:client
```

按实际源码位置调整路径。测试覆盖会话暂停、显示模式切换、存档兼容和卸载清理。设置好环境变量后，`npm test` 也会包含这一项集成测试。

## 从 Harness 源码启动预览

在 Whileplay 根目录运行：

```powershell
./scripts/start-local.ps1 -HarnessRoot '../deepseek-harness'
```

也可以先设置 `DSH_SOURCE_ROOT`，再直接运行 `./scripts/start-local.ps1`。脚本构建插件、生成本地 overlay，通过官方 `dsh web --patch` 入口启动，只在本次进程中加载插件，不修改 Harness 源码或安装到现有 profile。

脚本默认沿用 Harness 的数据目录。下面的命令使用独立数据目录和系统分配的端口：

```powershell
$env:DSH_HOME = Join-Path (Get-Location) '.runtime/local-home'
./scripts/start-local.ps1 -HarnessRoot '../deepseek-harness' -HarnessArgs '--no-open','--port','0'
```

## 真实页面测试

设置好 `DSH_SOURCE_ROOT`，并准备其 Playwright 依赖和可启动的浏览器，再运行：

```sh
npm run test:host
```

Windows 默认使用本机 Edge；其他平台默认使用 Playwright 的 Chromium。可用 `WHILEPLAY_BROWSER_CHANNEL` 指定已安装的浏览器，例如 PowerShell 中设置：

```powershell
$env:WHILEPLAY_BROWSER_CHANNEL = 'chrome'
```

测试通过 `dsh` profile 启动临时服务，不向模型发送请求。检查范围包括三个游戏、暂停恢复、搜索分类、主题切换、窗口与极简模式、列表滚动和窄屏布局。

每次运行使用独立的 `.runtime/host-smoke-*` 数据目录，截图写入 `artifacts/`。测试结束后关闭服务与浏览器，保留数据以便排查失败。列表压力测试追加的临时 DOM 行只用于检查布局，不代表新增可玩游戏。

## 源码结构

| 路径 | 用途 |
| --- | --- |
| `index.js`、`cordis.patch.yml` | 宿主入口与插件加载声明 |
| `src/ui.js`、`src/arcade.css` | 界面、主题、交互与会话联动 |
| `src/engine.js` | 游戏目录、飞机大战和贪吃蛇 |
| `src/tank.js` | 坦克地图、敌方行为、碰撞、精英坦克与可达补给位置 |
| `src/mission-game.js`、`src/ground-mission.js` | 三款游戏的任务适配、道具效果、演练与状态绘制 |
| `src/flight.js`、`src/flight-save.js` | 飞机局内成长、伤害处理、会话存档与恢复校验 |
| `src/window.js` | 窗口边界、移动与缩放比例 |
| `scripts/build.mjs` | 生成客户端分发入口 `client.js` |
| `tests/` | 游戏规则、窗口和客户端交互测试 |

会话联动使用 `conversation.input.left` 插槽提供的 `sessionId`、`useSessionStatus` 和 `useProjection`。宿主入口在官方 `sessionProjections` 注册 `whileplayMission`，纯函数折叠 `turn/start`、`tool/call`、`tool/result`、`step/end`、`turn/end`；不修改任务、不调用工具。投影只包含工具名称、调用标识、状态与统计，不包含参数、输出或会话文本。投影最多保留 128 条调用，优先保留运行中的调用。

飞机大战将工具类别映射为扫描机、运输机、装甲机和重装机，分别提供预警散射、货舱补给、侧翼弱点与周期护甲、锁定位置后的蓄力重炮。工具调用只负责触发入场，完成或失败只更新状态，不改变已入场敌机的运动、攻击与生命周期。工具目标最多两架，按双机编队入场，编队清空后间隔 1.2 秒；等待队列最多 12 架，超出部分每四次调用折算一份额外双发补给，待发额外补给最多三份。所有调用仍计入真实任务统计。工具稀疏时普通敌机继续出现，有工具敌机在场时降低普通敌机生成频率。

局内成长保存在 `game.flight`。新的 Step 会累积成长机会，在第 1、3、6、10…个新 Step 提供一次二选一，最多九次；各条路线最多三级。火力为双发、散射、穿透；生存为一次护盾、每 18 秒再生护盾、每局一次紧急救援；机动每级提高 16% 移速，第三级可擦弹得分，每五次擦弹获得双发增益。穿透弹用有界的命中记录避免连续帧重复伤害同一工具敌机。升级胶囊保留九秒，错过后选择保留；拾取、按钮、画布内数字 1 / 2 共用同一个升级函数，一次只取一个。暂停或有宿主待处理交互时不能选择。

飞机存档由 `src/flight-save.js` 管理，使用版本化的浏览器 localStorage，最近八个会话分别保存。每秒、暂停、工具投影更新、切换游戏/会话、页面离开及组件卸载时尝试保存；失败时显示存储提示。加载验证有限数值、路线等级、数组容量、调用与实体结构，拒绝损坏存档；恢复时重接当前轮调用引用。已生成的敌机、子弹、道具、待领取选择及演练时间均保留，旧轮敌机不会错误绑定到新轮同名 ID。恢复后始终等待手动继续，并提供 1.5 秒准备时间，准备期不推进游戏或演练时间。重新开局、重新开始演练覆盖当前会话的飞机存档。坦克与贪吃蛇仍保留原有页面内进度规则。

每个新的 `step/end` 触发一份补给；按轮内 Step 编号去重，初次打开或重新开局不补发历史奖励。密集结束的 Step 进入计数队列，补给间隔至少 1.8 秒，画面上已有 6 份补给时暂缓入场。双发占 65%，护盾占 25%，炸弹占 10%。双发持续 8 秒，重复拾取刷新时长；护盾抵挡一次且不叠加；炸弹清除敌方子弹、击毁普通敌机并对 Boss 造成 6 点伤害。道具需要接住，拾取 +20 分；未接住的道具飞出底部后消失。持续效果使用游戏时间，暂停期间不倒计时。

坦克与贪吃蛇复用同一个宿主投影、历史水位与 Step 去重适配器。坦克从空闲入口生成最多两辆三血精英坦克；Step 道具通过玩家位置的通道 flood-fill 选择可达空格，效果为连发、护盾和炸弹。贪吃蛇的工具目标是限时果实，Step 道具为双倍、护盾和减速，位置排除蛇身、普通食物及已有道具。地面道具与果实保留 12 秒，不依赖工具执行结果。近满盘时可以移除额外奖励来给普通食物腾出空格，避免提前结束游戏。

坦克与贪吃蛇的「联动演练」用同一适配器播放 29 秒的本地模拟事件，包含并行调用、失败、再次调用和 6 个 Step 结束；在第 1、4、7 秒依次触发每款游戏对应的三种道具，后续重复一轮。坦克需等待可达空格，玩家需要移动拾取或吃到道具来触发效果。界面和画布持续标注演练，不会发送模型请求；飞机演练使用同一适配器的 42 秒场景，保留原有四类工具并加入 16 次密集调用，共 21 次工具调用与八次 Step；演练以一次护盾开始，包含多次成长选择。演练战败仍按游戏规则结束，可重新启动。真实任务开始时退出演练并以干净战场接入真实投影。有待处理交互或真实任务运行时不能启动演练。

验证真实宿主的 Session 事件、投影注册、变化通知和卸载（不调用模型）：

```powershell
$env:DSH_SOURCE_ROOT = 'D:/dsh/deepseek-harness' # 改为实际路径
Push-Location $env:DSH_SOURCE_ROOT
node --import tsx/esm C:/path/to/dsh-whileplay/scripts/projection-smoke.mjs
Pop-Location
```

状态不可用或有 `pendingInteraction` 时暂停，恢复后由用户手动继续。

## 小队护送远征原型

游戏库中的「小队护送远征」采用俯视角实时护航。方向键或 WASD 控制战机，也可在画布上拖动；自动锁敌射击，Q 消耗工程支援修复运输船并短暂提供护盾，空格提供 0.23 秒冲刺与短暂无敌（2.8 秒冷却），E 消耗空袭支援清除杂兵、敌弹并对旗舰造成 24 点伤害。敌机持续接近并攻击运输船，战机与运输船均可受损，任一生命耗尽会结束护航。

`src/escort-action.js` 提供纯规则、绘制和版本化存档校验；`src/escort-action-ui.js` 负责输入、动画循环与宿主状态暂停。默认「当前会话」模式使用真实投影；「联动演练」保留 62 秒的番茄钟示例，按模拟时间触发工具补给、Todo 航点变化、15/36 秒的两架子 Agent 僚机、31 秒的模拟交互暂停以及最终交付入港。模拟允许或拒绝后，均需手动继续；奖励相同，拒绝分支使用替代检查说明。演练不调用模型、不执行工具。

真实模式由 `escort-mission.js` 注册的 `whileplayExpedition` 投影提供本轮用户请求摘要、起始时间、停止原因和明确呈交的文件名，配合宿主 `title`、`todos`、`subagentCatalog` 及 `whileplayMission`。`src/escort-live.js` 负责转换：Todo 是真实航程节点；新工具调用产生拦截机，成功返回产生火力补给，Step 结束产生护盾；确认本轮完成的子 Agent 提供最多两架僚机；`deliverables/presented` 文件装船。历史已完成调用不会补发奖励，运行中的调用可以在首次打开时入场，快速调用返回不会使敌机消失。子 Agent 仅停止不等于完成，外部 Agent 和缺失状态不推定完成。复用子 Agent 需观察到本轮运行证据，无法确认时不展示为本轮完成。

没有真实数据时显示空态，不回退演练任务，也不按 62 秒脚本推进或判定成功。任务停止、权限交互、焦点丢失时暂停战场，任务信息仍同步，恢复需手动操作。两模式按会话分别存档，真实模式使用 `dsh-whileplay.escort-live.v1:<sessionId>`；请求、Todo 文本、Agent 名称和交付文件名只保留在运行内存，不写入游戏存档；工具参数、输出与文件内容不进入游戏。

存档按会话隔离，每秒以及暂停、收起、离开页面时保存。刷新后恢复为暂停状态。真实会话存在待处理交互或状态未知时禁用战斗；失焦、隐藏页面或调整窗口也暂停。UI 测试覆盖 WASD、Q 技能、暂停和真实交互冻结；规则测试覆盖完整演练、碰撞、补给、双僚机、交付、存档与只读绘制；真实宿主验收覆盖战斗、技能、刷新恢复和窄屏。

实时护航的战斗成长：侦察机、快速突袭机、扇形射击重装机按编队生成；18/49 秒各进入一架旗舰，攻击前锁定玩家当时位置并显示红线预警，随后发射五发扇形弹。连续三秒内击落延续连击，每五连击增加一档得分倍率，最高四倍；受击中断连击。敌机掉落能量，105 范围内磁吸，每五个能量提升一级火力，最多三级，依次增加双发、单发伤害。工具火力补给仍提供限时三发超载。旗舰掉落空袭与火力补给。结算按船体耐久与旗舰击破数给出 S/A/B 评级，最佳得分以独立本地键保留，重开不会抹去。海面、尾焰、命中闪烁、碎片、得分浮字、冲刺残影、技能闪光和镜头震动均为 Canvas 实时绘制。规则测试覆盖编队、预警、冲刺、倍率、拾取成长、旧存档迁移及完整通关。

护航战场使用 480×720 纵向坐标，战机与运输船均朝上，Todo 阶段使运输船沿中轴向前推进；海面、岸线向下滚动，船尾航迹向后扩散，不绘制路线虚线或航点圆圈。窗口内画布按可用高度限制尺寸，保留底部技能操作区。存档版本 3，继续沿用会话键；横向版本 2 自动迁移实体、弹速与朝向布局，保留战斗和成长，恢复后手动继续。

实体航程地标由 `src/escort-terrain.js` 绘制：四段 Todo 分别映射雷达岛、补给岛、礁石水道、交付港。位置由模拟时间和对应阶段的预计抵达时刻推导，与海面以每秒 24 像素同速下移；上一地标离场时下一地标自然进入。雷达、仓库栈桥、礁石浪花及港口码头用于辨识节点，主航道为运输船留白。它们是俯视地景，飞机和空中子弹从上方经过；不会额外结算任务、发放奖励或改变碰撞规则。地景无新增存档字段，暂停、刷新恢复与战斗共用模拟时间；顶部航段编号与 Todo 状态共用同一函数。

战场内任务表达由 `src/escort-task.js` 提供：顶部显示模拟任务名称、当前 Todo、已完成 Todo 数量和战斗状态；地标直接标注 Todo 标题与状态；工具补给保留 `source` 和 `born`，绘制带降落伞的补给箱以及工具名和效果；返航僚机显示界面/逻辑 Agent 身份。逻辑 Agent 在 36 秒返回时将 `pomodoro.html` 装船，49 秒检查结束时装入使用说明，运输船旁持续显示交付清单，62 秒完成入港。补给与装船只由演练事件触发一次，显示不触发工具或改变权限。美术由 `src/escort-art.js` 负责金属战机、货船、波纹和环境光；水纹使用无会话数据的可选 OffscreenCanvas 缓存。任务信息已进入战场，右侧保留任务简报。
